# Phase 11.10: API & Task Integration — Threat Model

## 1. Scope & Adversary Capabilities
Phase 11.10 governs the API and task execution boundary for distribution shift analysis across multi-tenant deployments, CI/CD pipelines, and air-gapped auditor consoles.

### Adversary Model
- **Untrusted API Client / Tenant**: Attempts cross-tenant data leakage, task hijacking, denial-of-service via oversized payloads, or race condition exploitation.
- **Resource Exhaustion Attacker**: Attempts CPU/memory exhaustion via high-frequency concurrent job submission or massive representation/embedding drift requests.
- **State Manipulator**: Attempts out-of-order event submission, idempotency key collisions, or cancellation deadlocks.
- **Attribution Slanderer**: Attempts to manipulate API response interpretations to falsely accuse data contributors of malicious tampering based on ordinary statistical drift.

## 2. Exhaustive Threat Scenario Analysis (30 Threats)

| Threat ID | Threat Category | Attack Vector / Description | Affected Boundary | Architectural Mitigation | Residual Risk | Verification Method |
|:---|:---|:---|:---|:---|:---|:---|
| **T-11.10-001** | BOLA / Unauthorized Access | Attacker attempts to read another tenant's task or result via guessed UUID. | `GET /drift/analyses/{id}` | Object-level authorization: `task.project_id == path.project_id`. Mismatch returns generic `404 Not Found`. | Zero | Unit test with cross-project task lookup |
| **T-11.10-002** | Cross-Project Dataset Ingestion | Client passes dataset IDs belonging to Tenant B inside Tenant A's analysis request. | `POST /drift/analyses` | Validates dataset ownership in database under `project_id` before task registration. | Zero | Integration test with cross-project dataset IDs |
| **T-11.10-003** | Task ID Enumeration | Attacker attempts sequential integer or pseudo-random guessing of task IDs. | Task Registry | Cryptographically secure UUIDv4 identifiers generated for all operational tasks. | Negligible ($2^{-122}$) | Code inspection of UUID generator |
| **T-11.10-004** | Idempotency Key Collision Abuse | Client reuses an idempotency key with altered analytical payload to hijack previous results. | Task Registry Idempotency Map | Binds idempotency key to `request_fingerprint` (RFC 8785 JCS + SHA-256). Payload mismatch triggers `409 Conflict`. | Zero | Idempotency collision test suite |
| **T-11.10-005** | Task Flooding / DoS | Client spams thousands of analysis requests to saturate memory and thread pools. | Task Manager Queue | Bounded in-memory task registry ($M \le 1000$ active tasks per project) + `ThreadPoolExecutor` bounded queue. | Minimal | Load test asserting `429 Too Many Requests` |
| **T-11.10-006** | Memory Exhaustion via Payloads | Client sends a request with tens of thousands of feature columns or giant raw images. | API Request Validation | Strict Pydantic input bounds ($N \le 5000$, $D \le 4096$, image bytes $\le 20\text{MB}$). | Zero | Boundary validation test with oversized payloads |
| **T-11.10-007** | CPU Exhaustion via Representation Drift | Client requests high-dimensional MMD permutation tests with excessive repetitions. | Engine Dispatch | Permutation count bounded to $B \le 100$ and sample count $N \le 5000$. | Zero | Permutation parameter validation test |
| **T-11.10-008** | Incompatible Population Bypass | Client submits incompatible feature sets (e.g. continuous vs categorical mismatch). | Phase 11.2 Boundary | Mandatory Phase 11.2 `ComparisonBoundaryEngine` execution before hypothesis testing. | Zero | Boundary compatibility integration test |
| **T-11.10-009** | Cancellation Race Condition | Client calls cancel while task is completing or already failed. | Task State Machine | Atomic state transitions protected by `threading.Lock`. Validates state before applying `CANCEL_REQUESTED`. | Zero | Concurrent cancel/complete stress test |
| **T-11.10-010** | SSE Connection Starvation | Client opens hundreds of SSE connections without closing them, leaking memory and threads. | SSE Router | Bounded subscriber queue size (100 events) + automatic cleanup on client disconnect in `finally` block. | Minimal | SSE connection leak test |
| **T-11.10-011** | Event Replay Manipulation | Client attempts to alter event sequence or replay old progress events to deceive UI. | SSE Event Generator | Monotonically increasing `sequence_number` + immutable event objects generated server-side. | Zero | SSE sequence monotonicity test |
| **T-11.10-012** | Terminal Event Loss on Reconnect | Client drops connection before receiving `task.completed` event. | SSE Buffer | In-memory ring buffer retains last 50 events; replays events matching `Last-Event-ID`. | Minimal | SSE reconnect replay test |
| **T-11.10-013** | Result Hash Tampering | Attacker attempts to alter statistical findings before client read-back. | Result Model | Result response includes cryptographic `analysis_result_hash` and `integrated_profile_hash`. | Zero | Hash integrity verification test |
| **T-11.10-014** | API Parameter Fuzzing / NaN Injection | Client submits `NaN`, `Inf`, or negative confidence/threshold values. | API Request Schemas | Pydantic V2 `@field_validator` enforcing finite floats and bounded ranges $[0.0, 1.0]$. | Zero | Fuzzing unit test with NaN/Inf values |
| **T-11.10-015** | Analysis-Type Confusion | Client requests `IMAGE` drift on tabular dataset or `SOURCE` drift without metadata. | Request Dispatcher | Explicit modality validation matching dataset modality to requested analyzer. | Zero | Modality mismatch test |
| **T-11.10-016** | Dataset Version Staleness | Dataset is mutated concurrently while drift analysis task is in flight. | Population Extractor | Binds to immutable `DatasetVersionModel` and verifies `dataset_hash` before execution. | Zero | Concurrent dataset mutation test |
| **T-11.10-017** | Provenance Chain Detachment | Analysis result returned without binding to cryptographic audit trail. | Provenance Service | Automatically records `AuditEvent` and creates `ProvenanceRecord` upon task completion. | Zero | Provenance ledger linkage test |
| **T-11.10-018** | Evidence Layer Confusion | Detection findings accidentally exposed as cryptographic proofs in API response. | API Schemas | Strict separation of `EvidenceLayer.DETECTION` and `EvidenceLayer.PROOF` in response models. | Zero | Schema layer separation test |
| **T-11.10-019** | Risk / Decision Recomputation | API layer attempts to alter or recompute risk score/disposition. | API Service | API layer acts strictly as a passthrough for Phase 11.9 `IntegratedAssuranceProfile`. | Zero | Zero-recomputation assertion test |
| **T-11.10-020** | Information Leakage in Errors | Internal stack traces, SQLite paths, or memory addresses leaked in error envelopes. | Error Handler | Generic `ApiErrorResponse` with sanitized `code`, `message`, and sanitized `details`. | Zero | Error response sanitization test |
| **T-11.10-021** | Concurrent Task Worker Race | Multiple worker threads pick up the same task ID concurrently. | Task Registry | Strict single-submission guarantee; task execution managed exclusively via thread pool futures. | Zero | Concurrency stress test |
| **T-11.10-022** | Duplicate Task Execution on Retry | Transient network drops cause client to re-POST identical request. | Idempotency Map | Idempotency lookup returns existing active/completed task without re-executing. | Zero | Repeated POST retry test |
| **T-11.10-023** | Stale Result Retrieval | Client reads result from an aborted or cancelled task. | Result Endpoint | `GET .../result` raises `409 Conflict` (`ANALYSIS_NOT_COMPLETED`) if status $\ne$ `COMPLETED`. | Zero | Result retrieval on cancelled task test |
| **T-11.10-024** | Partial State Corruption on Cancel | Cancelling mid-analysis leaves incomplete evidence in database. | Cancellation Handler | Partial findings/evidence are discarded and not committed to SQLite if cancelled. | Zero | Cancellation database cleanliness test |
| **T-11.10-025** | High-Cost Representation DoS | Submitting large batches of un-normalized high-dimensional embeddings. | Phase 11.6 Engine | Maximum embedding dimension $D \le 4096$, batch size $N \le 5000$, and enforced L2 normalization. | Zero | Embedding dimension boundary test |
| **T-11.10-026** | Contributor Privacy Violation | API exposes raw contributor names, emails, or unsalted identifiers. | Source Analyzer API | Only exposes project-scoped pseudonymized identifiers (`source_group_id`). | Zero | PII leakage audit test |
| **T-11.10-027** | Attribution Slander Exploitation | Client uses API drift outputs to falsely claim contributor is an attacker. | Response Rationale | Rationale strings strictly enforce observational language ("observed statistical shift"). | Zero | Rationale language inspection test |
| **T-11.10-028** | Offline Air-Gap Breach | API endpoint attempts outbound HTTP call for policy or schema retrieval. | Network Boundary | 100% offline standard library + local SQLite execution. | Zero | AST network import scan |
| **T-11.10-029** | Database Schema Desynchronization | API changes attempt to introduce unversioned SQLite tables or columns. | Persistence Layer | 0 database schema migrations; strictly uses existing tables. | Zero | SQLite migration audit |
| **T-11.10-030** | False-Safe Optimization | Sub-threshold or incomplete modality analyses incorrectly mapped to `ACCEPT`. | Decision Mapping | Missing modalities trigger `INSUFFICIENT_DATA` and fail-closed to `REVIEW`. | Zero | Fail-closed missing modality test |
